# 秋招面试讲解指南

## 30 秒项目介绍

“我做了一个面向法律和财务场景的 PDF 证据提取工具。用户可以批量上传企业财报，输入中英文指标，系统会逐页定位相关内容、保留原始证据页，并输出规范命名的 PDF、Excel 和 Word 清单。MVP 不依赖外部大模型，采用可解释的页级匹配与邻近数值提取，因此数据不出本地、结果可追溯，也便于控制成本。”

## 为什么做

人工从多份年报中查找同一指标时，真正耗时的不只是“找到数字”，还包括确认来源页、统一命名和汇总证据链。这个项目把这些重复步骤合并为一条流水线。

## 技术亮点

1. **证据链优先：** 不只返回答案，还复制原始 PDF 页面并记录来源、页码、命中词和片段。
2. **可解释检索：** 用户只输入一个指标，系统通过版本化的多语言指标词典扩展近义词；如果正文存在精确指标金额，就不会混入更宽泛的会计科目。
3. **避免“伪精确”：** 金额必须满足指标语义、数值和单位上下文，章节编号、人数、专利数和比例会被排除；未明确写出的币种不会自行推断。
4. **模块边界清楚：** 解析、检索、元数据、导出和界面分离，后续可替换 OCR 或语义检索模块。
5. **隐私意识：** MVP 默认本地处理；生产方案会增加权限、加密、留存策略和审计日志。

## 架构取舍

- 选择 Streamlit 是为了快速形成可操作的演示，不代表生产前端最终形态。
- 选择 pypdf 同时做文本提取和原页复制，证据页不会因重新排版而失真。
- 没有一开始接入 LLM：多语言指标词典、结构规则和内容元数据识别已经能解决首版核心问题，且结果可重复、成本为零。语义模型更适合作为未知指标扩词或低置信度复核层，而不是唯一事实来源。
- OCR 未放进首版，因为它会引入模型体积、平台依赖和新的置信度问题；界面会主动识别“疑似扫描件”。

## 可能追问

**如何减少误报？** 让用户提供中英文同义词；提高阈值；结合段落距离、表格表头、单位和年份做二次排序；最终保留人工确认。

**如何支持扫描件？** 先做页面图像化和方向校正，再使用 PaddleOCR/Tesseract；将 OCR 置信度写入结果，并保存页图作为证据。

**如何支持 1,000 份文件？** 将界面与 API 分离，文件放对象存储，解析任务进入队列；按文件哈希缓存页文本，批量检索复用索引。

**如何评估？** 建立人工标注集，分别统计页级 Recall@K、正确数值率、字段级覆盖率和单份文档耗时；法律/财务场景优先保证召回，再由人工确认精度。

**安全怎么做？** 文件加密、租户隔离、最小权限、短期留存、下载水印、访问审计；敏感场景使用私有化 OCR/模型。

## 演示顺序（3 分钟）

1. 上传两份不同企业/年份的 PDF。
2. 输入“研发投入”及英文同义词。
3. 展示候选页、命中词、片段与数值候选。
4. 下载 ZIP，打开规范命名的证据页和 Excel。
5. 说明扫描件/OCR 限制以及下一版路线。
